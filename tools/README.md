# Asset tools

The walk builder assembles character-specific source parts against retained semantic pose masks from Caelan's approved cycles.

```sh
python -m pip install -r tools/requirements-assets.txt
python tools/build_character_walk.py mira
python tools/build_character_walk.py mira --direction all
python tools/build_character_walk.py npcs/male_01
```

Run these commands from the repository root using Python 3.12. In the current cloud environment, `/workspace/.venvs/project-jrpg/bin/python` already has the dependency installed.

Use `--refresh-template` to regenerate shared masks before assembling the character. The builder reads the recipe, idle and approved reference sprites, writes derived template/source components when requested, and writes the frame PNGs, sheets, JSON and looping review GIFs. The source idle and approved references remain unchanged.

`--direction` accepts `front`, `left`, `right`, `back`, or `all`. Front remains the default. Each direction has its own appearance input, recipe and material masks. `all` also exports a combined native sheet, metadata, and labeled four-direction comparison GIF. Approval labels come from each recipe.

New characters need a recipe and appropriately prepared appearance parts. Shared semantic arm masks allow clothing recoloring; shared leg art can retain matching trousers/boots or use an explicit leg-color mapping. Other body proportions or costumes can use additional pose components rather than deforming a flattened idle image.

The base male NPC front walk uses the same arm and leg poses with an explicit `leg_palette` mapping for tan trousers and brown boots. A recipe with `shared_leg_costume: false` must supply that mapping; unmapped source colors are rejected. `preserve_waist: true` retains the original belt/buckle and upper-trouser pixels instead of synthesizing a waist. Both options are opt-in, preserving the existing Mira output. Character directories may use identifier components separated by `/`, such as `npcs/male_01`; absolute paths and traversal components are rejected.

Male NPC front-idle palette variants are rebuilt with `python tools/build_npc_palette_variants.py`. The builder reads the approved native `male_01` frame and the retained `assets/source/characters/npcs/male_01/palette_variants.json` recipe. Exact replacements within material regions preserve the silhouette, shading layout and transparency. Shade aliases include brown hair highlights exported with shared leather colors, while keeping the belt and boots unchanged. It writes variants 02 and 03, their enlarged previews, a native three-frame sheet and a labeled review comparison. Existing approval statuses are preserved on rebuild.

For all four male NPC idle directions, run `python tools/build_npc_palette_variants.py --direction all`. It recolors the retained base views, preserves each frame's existing approval status and exports per-character 96×36 sheets plus the combined 96×108 sheet and labeled 12× review grid. `--direction left`, `right` or `back` rebuilds only that direction's variants and metadata. The default remains `front` for compatibility.

To re-export the three new base appearances from their retained concept, first run `python assets/source/characters/npcs/male_01/directions/export_idles.py`. Its source-specific registration bands and palette/feature rules are recorded in the adjacent `export.json`. This appearance export does not generate walking poses or edit the approved front art.

Build the two front-walk palettes and a synchronized three-NPC review with `python tools/build_npc_walk_variants.py`. The helper derives recipes from the approved base walk, reads the existing palette overrides, uses each approved palette idle for the head/waist and calls the shared walk builder. It replaces shirt and trouser material colors while keeping the leg silhouettes, boots, skin, belt, phases and bob. Existing recipe approval statuses survive rebuilds. The base walk is read only.

Outputs include each variant's four native frames, sheet, metadata, posed source parts, static strip and looping previews. `assets/characters/npcs/male_walk_front_variants.png` is a native 96×108 sheet with variants as rows and phases as columns. Its JSON records timing, anchors and per-variant animation status; `_review.gif` shows all three in synchronized 16× columns and `_review.png` is the first phase. `--direction` can select another direction after its base walk is approved.

The base male NPC has approved left, right and back walk recipes. Rebuild all base directions and the labeled four-direction comparison with `python tools/build_character_walk.py npcs/male_01 --direction all`. These use the already-approved directional idles and retained shared pose masks. The original front walk remains unchanged. The palette helper can derive each remaining direction from these approved base cycles.

Rebuild all male walking palettes and review boards with `python tools/build_npc_walk_variants.py --direction all`. This preserves all existing approval statuses, rebuilds variants 02/03 from the approved base recipes, and writes per-character directional sheets/previews plus a complete synchronized grid at `assets/characters/npcs/male_walk_all_variants_review.gif`. Its rows are front, left, right, back; columns are palettes 01, 02, 03. The corresponding native sheet is 96×432, grouped by direction then palette, with four playback phases as columns; its JSON records every frame rectangle and animation status. The base cycles remain read-only.

The first female NPC front idle is exported with `python assets/source/characters/npcs/female_01/export_idle.py`. Its source-specific registration, alpha and material rules are retained in the adjacent `export.json`. This produces the 24×36 idle, named palette, nearest-neighbor review/comparison images and four appearance layers. The dress uses its own silhouette; this export does not generate other facings or walking frames.

Female front-idle palettes are built with `python tools/build_female_npc_palette_variants.py`. It reuses the existing material-region recolor helper, applies explicit eye landmarks, exports variants 02/03 and their appearance layers, and writes the native 72×36 sheet plus labeled 16× sprite and 32× eye comparisons. Its recipe is `assets/source/characters/npcs/female_01/palette_variants.json`; all frame approval statuses are preserved. Skin, outlines, boots, silhouette and shading placement are unchanged. The first palette's two blue iris pixels are exported from its frame metadata by the source exporter, so run that exporter first after changing base appearance or eye settings. The default command rebuilds front palettes only.

Female side/back base idles are exported with `python assets/source/characters/npcs/female_01/directions/export_idles.py`. The retained turnaround source and `directions/export.json` record panel crops, row registration, material ramps and explicit feature cleanup. This registers the low bun, waist, row-28 hem, calves and boots to the approved front scale. Profiles have one pupil/iris pair; the back has no eye landmarks.

Then run `python tools/build_female_npc_palette_variants.py --direction all` to rebuild all idle palettes and comparisons, preserving each frame's approval status. It changes hair/dress ramps and profile iris accents without changing skin, boots or silhouettes. Each character receives a native 96×36 directional sheet and labeled 12× review. The combined native sheet is 96×108; its 1152×1488 review uses palette rows and front/left/right/back columns. Profile eye crops are enlarged 32×. Individual `--direction left|right|back` options rebuild only that direction's palette frames; `all` also refreshes the combined sheets. These are stationary appearances and appearance layers; walking still needs dedicated dress poses.

Build the blue female NPC's approved front walk with `python tools/build_dress_walk.py`. It reuses the shared appearance, semantic arm and preview helpers plus the approved front stride template. Its `assets/characters/npcs/female_01/walk_front/recipe.json` adds explicit skirt row poses and calf/ankle-boot boundaries. This preserves shared foot silhouettes and coordinated head/neck/shoulder bob while adding one-pixel skirt sway and passing hem lift. It exports native frames, sheet, metadata, editable posed layers, a 12× static strip, a 20× loop and a synchronized Caelan comparison. Existing approved idles, templates and other animation builders remain unchanged. Approval status is read from the recipe; the default command rebuilds only the approved blue base front cycle.

`python tools/build_dress_walk.py --direction left|right|back` selects a new base cycle; `--direction all` rebuilds all four and their labeled comparison. The three new directions use their own approved idles and shared directional templates. Profile arm masks exclude source neck pixels within the bodice, then restore the character's approved neckline so shoulder bob cannot stretch the neck. Per-phase `leg_split_x` and `boot_top_rows` adapt short boots to overlapping strides; the original leg alpha remains exact. The back has no eyes, while profiles keep one blue iris. Recipe approval statuses are preserved, and rebuilding the approved front produces identical files. The combined native sheet is 96×144, with four phases as columns and front/left/right/back as rows; its metadata records individual cycle statuses. The review GIF shows those directions side by side at 12× scale and 140 ms per frame. Individual loops are 20×.

Build female walking palette variants with `python tools/build_female_npc_walk_variants.py --direction all`. The default without `--direction` builds front only. Each selected base cycle must be approved. The helper applies the existing approved hair/dress/iris colors to complete base frames and retained posed parts, changing no positions or motion data. Complete-frame named-color replacement includes raised shoulders and skirts; idle-only region rectangles are not used for animation. Each derived recipe retains the approved stride/costume parameters and records its source animation, explicit color map and independent approval status. Previously approved base packs, palettes and idles are read only.

Outputs include eight approved palette cycles with native frames, 96×36 sheets, metadata, bob-adjusted eye landmarks, source layers, 12× strips and 20× loops. `--direction all` also writes each palette's four-direction board and a complete synchronized review grid. `female_walk_<direction>_variants_review.gif` shows all three palettes at 16×; `female_walk_all_variants_review.gif` shows directions as rows and palettes as columns at 12×. All loops retain the base's four phases at 140 ms each. Native per-direction sheets are 96×108; the complete native sheet is 96×432, grouped by direction then palette with phases as columns. JSON records all animation statuses, timing, anchors and frame rectangles. Back views never receive iris pixels. Existing variant approval statuses survive rebuilds.
