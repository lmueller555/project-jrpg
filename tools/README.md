# Asset tools

Terrain authoring, pack inventories, build/check commands, the playable grass
study and map-integration guidance are maintained together in the
[terrain art and pack creation standard](../docs/TERRAIN_ART_STANDARD.md).

Artwork, textures, sprites, animation, exporters and rendering changes follow the
[global visual art standard](../docs/VISUAL_ART_STANDARD.md).
That is the single reference for style, units, density, rendering, construction
and review; this catalogue records commands and asset-specific implementation
details. Full-scene 2× rendering is implemented; Sanctuary hall, bedroom and
dining, the full Eldenmere town/interiors, southern business lane and upstream are
migrated environments. Other regions and character banks retain their own status.
Use `python tools/profile_renderer.py --frames 30` for temporary-save
production draw timings.
Existing command descriptions and frame dimensions below describe their current
exports. During scoped migrations, update their density/anchor metadata and
runtime status using the central guide rather than interpreting old pixel
dimensions as new global limits. Older part/mask/layer builders remain
for reproducing approved assets, not as the construction method for new walks or runs.
Use the [running animation standard](../docs/VISUAL_ART_STANDARD.md#running-animations)
for near/far coupling, support/flight phases and run-specific review.
Do not rebuild approved references or migrate unrelated art as part of adopting
the standard.

compositions. `python tools/capture_eldenmere_hd.py /tmp/eldenmere-review` captures

refuses to overwrite the HD map; historical reproduction needs an isolated checkout.

The legacy shared walk builder assembles character-specific source parts against retained semantic pose masks from Caelan's approved cycles. The following commands document that existing implementation; new walks use complete authored drawings under the global standard.

```sh
python -m pip install -r tools/requirements-assets.txt
python tools/build_character_walk.py mira
python tools/build_character_walk.py mira --direction all
python tools/build_character_walk.py npcs/male_01
```

Run these commands from the repository root using Python 3.12. In the current cloud environment, `/workspace/.venvs/project-jrpg/bin/python` already has the dependency installed.

Use `--refresh-template` to regenerate shared masks before assembling the character. The builder reads the recipe, idle and approved reference sprites, writes derived template/source components when requested, and writes the frame PNGs, sheets, JSON and looping review GIFs. The source idle and approved references remain unchanged.

`--direction` accepts `front`, `left`, `right`, `back`, or `all`. Front remains the default. Each direction has its own appearance input, recipe and material masks. `all` also exports a combined native sheet, metadata, and labeled four-direction comparison GIF. Approval labels come from each recipe.

This legacy builder requires a recipe and appropriately prepared appearance parts. Its semantic arm masks support clothing recoloring and its shared legs support explicit color mapping for existing packs. These are implementation facts for reproducing those packs, not instructions to construct new character walks from separate body parts.

The base male NPC front walk uses the same arm and leg poses with an explicit `leg_palette` mapping for tan trousers and brown boots. A recipe with `shared_leg_costume: false` must supply that mapping; unmapped source colors are rejected. `preserve_waist: true` retains the original belt/buckle and upper-trouser pixels instead of synthesizing a waist. Both options are opt-in, preserving the existing Mira output. Character directories may use identifier components separated by `/`, such as `npcs/male_01`; absolute paths and traversal components are rejected.
